# 06 · 过程记录（决策、证据、边界、未决）

> 记录本次 180 分钟考核的实际执行轨迹，供评审复核"做过什么、为什么这样做、如何验证、哪些没做"。

## 1. 执行模型：1 人 + Agent 团队

本人担任**项目总监**，只做编排、门禁、验收、提交与对外汇报；产出按 S0–S5 分段派给 Agent 执行，主线程只接收结构化摘要（≤250 字），实现上下文隔离。

| 段 | 时间盒 | 执行者 | 产出 | 提交 |
| --- | --- | --- | --- | --- |
| S0 开题与仓库 | 0–10 min | 本人 | `git init`、目录、问题重述、README 骨架 | `9ac04f8` |
| S1 诊断 | 10–35 min | Agent（业务分析/PM 视角） | `docs/01-诊断报告.md` | `17af671` |
| S2 方案 | 35–70 min | Agent（架构 + PM 视角） | `docs/02`、`03`、`04` | `c09df43`、`a80b5b4` |
| S3 实现 | 70–140 min | 本人搭骨架 + 5 个 Agent 各负责一页 | `src/**`、5 个模块 | `5d992d1`…`0c095c3` |
| S4 测试与就绪 | 140–160 min | 本人 | 96 例测试、SSR 冒烟、`docs/05` | `44b0be6` |
| S5 交付 | 160–180 min | 2 个 Agent 补 Agent 库 + 本人收口 | `README`、`docs/06`、`dev-team/Agents/*` | 见 README 里程碑 |

隔离方式：每个 Agent 的 brief 自包含（客户背景、数字口径、技术栈、文件所有权、验收标准），互不依赖主线程长历史；并行上限 2–3；esbuild 语法检查避免并发构建冲突；合并后由本人统一 `npm run verify` 验收。

这本身就是被考核的 **L3 工作方式**：不靠"一个人写完所有代码"，而靠"可复用的角色 + 契约 + 门禁"，换一个客户时替换 brief 与种子即可复用。

## 2. 关键决策与理由

1. **范围锁死 2 片区 + 5 模块 + 45 万 / 8 周**。理由：8 周内可演示、可验收；用"青秀盈 / 西乡塘亏"做对照，才能直接回答"亏在哪"。放弃：全量 8 片区上线、移动端。
2. **技术栈对齐机器上已装的轻栈**（Vite 5.4.21 + React 18.3.1 + 纯 JS + Vitest 2.1.9）。理由：180 分钟内不冒装包失败的风险；原方案中的 TS、Zustand、Zod、Recharts、router 全部移除，改用自写 store、手写校验、SVG 图表、tab 切换。决策记录见 `a80b5b4`。
3. **业务规则一律纯函数**（`src/domain/**`），金额一律整数分。理由：提成与损益是评分重点，必须可单测、可复算、避免浮点误差；UI 只做展示。
4. **不持久化损益与提成**，由 selectors 实时重算。理由：明细一变就必须一致，避免"缓存账"与"明细账"打架。
5. **确定性种子**（固定随机种子 20261031，无 `Math.random()` / `Date.now()`）。理由：验收数字可复现、刷新一致、测试可断言。
6. **自写轻 store**（`useSyncExternalStore` + localStorage `njdao:v1`）。理由：零依赖、可 SSR（传 getServerSnapshot）、体积小；代价是无中间件与时间旅行，本期不需要。
7. **工单规模 5,200 → 1,800**。理由：演示与测试速度优先；营收/漏损口径不变，A1/A2 断言不受影响。偏差已在 `docs/03` §2.4 与 README §7 标注。
8. **测试不引 jsdom**，用 SSR（`react-dom/server`）证明 5 个页面可无崩溃渲染 + 手工演示脚本覆盖交互。理由：不增加依赖与配置时间；代价是点击级回归靠人工（已声明）。
9. **Agent 库作为正式交付**：8 个 Agent 全部补齐"职责边界 / 工作流 / 输入输出 / 知识库引用表 / 自检清单＋回传格式"，并把本项目真实路径、数字、命令写进正文，避免空泛人设。
10. **记分卡如实评分**：总档 Bronze，明确写出"无鉴权、无指标"两个短板，而不是自封 Silver。理由：评审要的是可审计的刻度，不是好看。

## 4. 过程中的偏差与纠正（如实记录）

- **技术栈漂移**：S2 初稿沿用了 TS/Zustand/Zod/Recharts/router，与机器已装依赖不符。发现后改为轻栈并单独提交说明（`a80b5b4`），同时把 `docs/03` 的目录、验证命令、人工验证路径全部对齐实现。
- **文档路径失真**：`docs/03` 曾写 `/orders/new`、`/payroll/:period` 等 URL 路由，实际是 tab 单页。已改为 tab 标识 + 实际交互描述，并删除未实现的登录/配置/审计页承诺。
- **种子规模失真**：文档写 5,200 单，实现为 1,800 单；已改文档并说明原因。
- **遗留别名文件**：`src/utils/format.js`、`src/data/seed.js` 是未被引用的兼容壳，已删除，避免"两份实现"的误导。
- **M2 页面 Agent 中途返回 502**：该 Agent 的会话异常结束，但文件已完整写入且构建通过；随后由 S4 的 SSR 冒烟与选择器集成测试覆盖其数据链路，未发现运行时崩溃。

## 5. 边界声明

1. 数据全部由确定性脚本虚构，不含任何真实客户、账号、手机号、地址或凭据。
2. 无后端、无数据库、无鉴权；localStorage 单机持久化，审批角色为函数入参模拟。
3. 短信/支付/地图/对象存储均未接入；照片、签字为 `mock://` 占位。
4. 未实现账期锁定/红冲、批量派单、通知、移动端与真实导出审计。
5. 浏览器交互未做 DOM 自动化，只做 SSR 冒烟 + 人工脚本。

## 7. L3 复用论证（对应公司资产指标）

- **人月产出**：45 万合同 ÷ 约 2.2 人月（8 周 × 1 人 + Agent 并行）≈ **20.45 万/人月**，高于 15 万门槛（计算过程见 `docs/04-商业方案.md`）。
- **复用率**：domain 纯函数、store、UI 组件、Agent 定义、验证脚本与文档模板均可跨客户复用，估算 **68.5%**（口径见 `docs/04`）。
- **第 3 个客户 ≤3 天**：替换种子与品牌/字段映射、沿用同一套 domain 契约与 Agent brief，即可产出同构看板；差异集中在行业指标与话术，不动底座。
- **病倒两周不停**：所有阶段有书面契约（docs/02、docs/03）、可执行命令（`verify`）与 Agent brief，接手者按文档即可继续；不依赖个人记忆。

3. 按 README §2 走一遍演示，核对 M5 的 −2.66 / +2.44 / −0.22 与 M2 的 40% 无法定责率。
4. 查看 `docs/05` 的 A1–A10 映射表，逐条打开对应测试文件。

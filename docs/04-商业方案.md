## 0. 一页结论

| 问题 | 结论 | 关键数字 |
| --- | --- | --- |
| 报价 | 45 万，一次交付 + 30 天陪跑 | 诊断 3 + 底座 9 + 模块 28 + 部署培训 5 |
| 现金安全 | **任何时点余额不为负，且始终预留 7.0 万返工资金** | 最差时点账面 8.6 万，扣除预留后 1.6 万 ≥ 0 |
| 人月产出 | **20.45 万/人月**（含返工的最坏口径仍 15.0 万） | 45 ÷ 2.2 人月；45 ÷ 3.0 人月 = 15.0 |
| 复用率 | **68.5%（按人日）**，高于 60% 门槛 | 35.6 ÷ 52 人日；代码行口径 67.7% |
| 第 3 个客户 | **3 天（24 小时）上线** | 配置 8h + 数据 8h + UAT/培训 8h |
| 客户 ROI | **满产 47.8 万/年**；含 70% 爬坡 3 年净收益约 66 万 | 回本 18.5 个月；3 年 ROI 105% |
| 业务连续性 | 病倒两周交付不停 | Agent 库 8 个 + SOP 8 段 + 代码库可交接；48h 可复现演练 |

**一句话**：45 万不是卖 8 周工时，是卖"一套能解释亏损、能复制到 8 片区、且我倒下也能跑"的经营系统。客户第一年满产收益约 47.8 万，基本覆盖投入；真正的价值在第二个、第三个片区不再重演"连亏 14 个月"。

## 1. 45 万报价拆分

### 1.1 总价与口径

| 项 | 内容 |
| --- | --- |
| 合同总价 | **450,000 元**（含税，假定 6% 增值税；若客户要求专票另议） |
| 计价方式 | **按交付结果与资产定价**，不按人头工时线性计价 |
| 包含 | 2 片区上线、5 模块、种子数据、UAT、培训、30 天陪跑、源码与文档交付 |

| 变更计价 | 新增模块 4–8 万/个；新增同业态片区 1.5 万/个（配置）；新增业务规则 2–5 万/条 |

### 1.2 拆分表

> 校验：3.0 + 9.0 + 6.0 + 5.0 + 6.0 + 4.0 + 7.0 + 5.0 = **45.0 万**。
> 内部工作量合计 3.0 + 8.0 + 6.5 + 6.0 + 6.5 + 3.5 + 6.5 + 3.5 = **43.5 人日 = 2.0 人月**（按 21.75 工作日/人月），与第 3 节口径一致。

### 1.3 为什么值 45 万（价值锚，不是工时锚）

| 锚点 | 数字 | 说明 |
| --- | --- | --- |
| 客户已发生的亏损 | 西乡塘连亏 14 个月，累计 **37.24 万** | 这不是未来收益，是已经付出的学费 |
| 客户年度可回收漏损 | 满产 **47.8 万/年**（含 8 片区复制） | 见第 6 节逐项算式 |
| 下一个"西乡塘"的代价 | 再亏 14 个月 ≈ **37 万** | 8 片区中只要再漏一个，系统就回本 |
| 合同额占客户年营收 | 45 ÷ 2,880 = **1.56%** | 相当于 4.7 天的公司营收 |
| 传统外包对照 | 2.5 万/人月 × 18 人月 = 45 万 | 同样价格，传统需 18 人月；本方案 2.2 人月，提效约 8.2 倍 |

**定价逻辑**：客户买的不是"代码行"，是"把 3.38 万/月亏损拆到可执行动作"的能力。若只按工时卖，2.2 人月 × 2.5 万 = 5.5 万，反而无法覆盖机会成本，也无法支撑后续资产沉淀。

### 1.4 变更与不含项

- 变更单必须写明：范围、金额、工期、验收标准，双方签字后生效。
- 单条新业务规则（如新增计价模型）2–5 万；新增同业态片区 1.5 万/个；跨业态（如维修、配送）需重新评估，不承诺 3 天。
- 差旅、第三方服务（短信/支付/对象存储）按实报销，不打包进 45 万。

## 2. 付款里程碑与现金流

### 2.1 付款节点（5 段，30/20/25/20/5）

| 节点 | 时间 | 比例 | 金额（万元） | 触发条件（可验收） |
| --- | --- | ---: | ---: | --- |
| P1 签约启动 | T+0 | 30% | **13.50** | 合同生效、范围确认书签字、数据边界声明签字 |
| P2 诊断+原型 | T+2 周 | 20% | **9.00** | 诊断复核通过；工单建/派/完成可演示；客户书面确认 |
| P3 核心闭环 UAT | T+5 周 | 25% | **11.25** | 工单→赔付→损益 v1 闭环通过；6 组对账中至少 2 组 0 元差 |
| P4 试点上线 | T+8 周 | 20% | **9.00** | 5 模块 UAT 100%；培训完成；上线确认书 |
| P5 稳定运行 | T+12 周 | 5% | **2.25** | 上线后 30 天无 P0/P1；月结陪跑一次成功 |
| **合计** | — | **100%** | **45.00** | — |

> 回款条款：每节点验收后 **7 个工作日内**付款；逾期 >15 天，我方有权暂停后续非关键工作（不影响已上线功能）。

### 2.2 现金流基线（保守口径：月固定支出 3.2 万；所有回款按"当月月末到账"计）

| 月份 | 期初余额 | 固定支出 | 当月回款 | **月内最低余额** | 月末余额 | 扣预留 7.00 后可动用（按月内最低） |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| M1（W1–W4） | 20.00 | 3.20 | 22.50（P1+P2，月末到账） | **16.80** | 39.30 | **9.80** |
| M2（W5–W8） | 39.30 | 3.20 | 20.25（P3+P4，月末到账） | **36.10** | 56.35 | **29.10** |
| M3（W9–W12） | 56.35 | 3.20 | 2.25（P5，月末到账） | **53.15** | 55.40 | **46.15** |
| **全期最低** | — | — | — | **16.80** | — | **9.80** |

> 现金安全的一条铁律：**先支后收**。上表刻意把回款全部记在月末，支出记在月初，因此"月内最低余额"就是任何时点的保守下界。全期最低 **16.80 万**，扣除 7.00 万返工预留后仍有 **9.80 万**，任何时点均不为负。

### 2.3 压力测试（三类坏情况）

| 情景 | 假设 | 最低月末余额 | 扣预留后可动用 | 结论 |
| --- | --- | ---: | ---: | --- |
| S1 回款全部延后 30 天 | 每个节点晚 1 个月到账 | 13.60（M2） | 6.60 | **安全** |
| S2 支出上浮至 3.8 万/月 | Token/云服务超支 0.6 万/月 | 12.40（M2） | 5.40 | **安全** |
| S3 最坏：全部 45 万第 3 月末到账，且支出 3.8 万 | 客户验收后一次性付款 | 8.60（M3） | 1.60 | **安全但触线** |
| S4 组合：S1 + S2 | 回款晚 1 月 + 支出 3.8 万 | 12.40（M2） | 5.40 | **安全** |

**S3 说明**：即使客户拖到项目结束才付全款、且每月多烧 0.6 万，账面最低仍有 8.6 万，扣除 7.0 万返工预留后剩 1.6 万，**不为负**。这是本方案的现金安全底线。

### 2.4 返工资金口径与金额

| 项 | 口径 | 金额 |
| --- | --- | --- |
| 返工周期 | 一次完整返工 = 8 周（按最坏情况重做核心模块 + 回归 + 重新 UAT） | 2.0 个月 |
| 生存成本 | 2.0 个月 × 月固定支出 3.2 万 | 6.40 万 |
| 弹性缓冲 | Token/差旅/临时服务 | 0.60 万 |
| **返工资金合计** | 覆盖 8 周内"零回款、零新增收入"的全部固定支出 | **7.00 万** |

- **锁定规则**：7.00 万自签约日起单独记账，不计入可用现金；仅在触发返工时释放。
- **触发条件**：① 核心规则（提成/损益/定责）出现系统性错误；② UAT 关键流失败且 5 个工作日内无法修复；③ 客户书面要求重做。
- **释放后补充**：P2 回款到账后，返工资金自动补足至 7.00 万。

### 2.5 现金结论

1. **任何时点余额不为负**：基线最低 16.80 万；最坏 S3 为 8.60 万；均 > 0。
2. **始终预留一次完整返工**：7.00 万在 4 类情景下均可覆盖，且扣除后最坏仍有 1.60 万。
3. **项目结束后 runway**：M3 末账面 55.40 万，按 3.2 万/月可支撑 **17.3 个月**，足以等待第二个客户签约。
4. **不需要外部融资**：启动现金 20 万即可覆盖到 P1 回款，不存在"发不出工资"的窗口。

## 3. 人月产出

### 3.1 口径

- **人月** = 人类有效投入时间（含判断、评审、客户沟通、验收），**不含 Agent 并行执行时间**；1 人月 = 21.75 工作日。
- **分子** = 合同额 45 万（不含硬件/差旅等代收代付）。
- 交付期 8 周 = 2.0 人月；30 天陪跑 = 0.2 人月；一次完整返工 = 0.8 人月（按 40% 返工系数）。

### 3.2 算式与结论

```
基准：45 万 ÷ 2.2 人月 = 20.45 万/人月
交付期：45 万 ÷ 2.0 人月 = 22.50 万/人月
最坏：45 万 ÷ (2.2 + 0.8) 人月 = 45 ÷ 3.0 = 15.00 万/人月
```

| 口径 | 投入人月 | 45 ÷ 人月（万/人月） | 是否 ≥15 |
| --- | ---: | ---: | :---: |
| 仅交付期（8 周） | 2.0 | 22.50 | 是 |
| 基准（含 30 天陪跑） | 2.2 | **20.45** | 是 |
| 含一次完整返工 | 3.0 | **15.00** | 是（恰好达标） |
| 传统外包同价对照 | 18.0 | 2.50 | 否（说明提效空间） |

**结论**：基准 **20.45 万/人月**，是 15 万门槛的 **1.36 倍**；即使把一次完整返工全部计入且不额外收费，仍**恰好达到 15.00 万/人月**。产出不是靠"熬夜"，而是靠：底座复用、规则纯函数化、Agent 执行 + 人只做判断与验收。

### 3.3 成本与毛利（内部口径，不向客户披露）

| 项 | 金额（万元） | 说明 |
| --- | ---: | --- |
| 项目全成本（2.2 月 × 3.2 万） | 7.04 | 含生活费、房租、云服务、其他 |
| Token / 第三方服务增量 | 0.60 | 8 周开发 + 30 天陪跑 |
| 合计成本 | **7.64** | — |
| 毛利 | **37.36** | 45 − 7.64 |
| 毛利率 | **83.0%** | 37.36 ÷ 45 |

> 全成本口径偏保守（固定支出本来就发生）；增量现金成本接近 0。高毛利用于覆盖返工风险与第二个客户的资产建设，不构成"暴利"——一人公司必须用毛利换生存窗口。

## 4. 复用率 ≥60% 的论证

### 4.1 口径

**复用率 = 第二个客户可直接复用资产的工作量（人日）÷ 第二个客户总工作量（人日）。**

- 以"第 2 个同业态客户"为计量对象，不是"第 1 个项目内部复用"。
- 只计**无需改代码**即可复用的部分；需要改配置的不计、需要改代码的更不计（保守）。
- 辅助口径：代码行复用率、Agent 可复用件数占比，用于交叉验证。

### 4.2 资产清单与计算

| 资产 | 第 2 客户工作量（人日） | 复用比例 | 复用（人日） | 类型 |
| --- | ---: | ---: | ---: | --- |
| 平台底座：路由、布局、错误边界、认证/角色/权限 | 8.0 | 100% | 8.0 | 通用 |
| 通用组件：表格、筛选、导出、图表、金额/状态组件 | 10.0 | 100% | 10.0 | 通用 |
| 数据模型 + Zod schema + store 脚手架 | 6.0 | 80% | 4.8 | 半通用 |
| 规则引擎：提成 / 质量系数 / 损益 / 定责 | 8.0 | 60% | 4.8 | 半通用（参数化） |
| Agent 库 + SOP + 测试 + 部署脚本 | 8.0 | 100% | 8.0 | 通用 |
| 客户定制：流程、字段、口径、主数据、培训 | 12.0 | 0% | 0 | 定制 |
| **合计** | **52.0** | — | **35.6** | — |

```
复用率 = 35.6 ÷ 52.0 = 68.5%
第 2 客户净新增工作量 = 52.0 − 35.6 = 16.4 人日 ≈ 3.3 周
```

### 4.3 交叉验证

| 口径 | 通用 | 定制 | 复用率 |
| --- | ---: | ---: | ---: |
| 人日（主口径，保守） | 35.6 | 16.4 | **68.5%** |
| 代码行（估算） | 8,800 行 | 4,200 行 | **67.7%** |
| Agent 件数 | 6 个 | 1 个（客户专属数据清洗） | **85.7%** |

**结论**：主口径 **68.5% ≥ 60%**，三种口径均过线。第 2 个客户仍需 16.4 人日，主要花在"口径确认、主数据清洗、培训"——这些是服务，不是代码，也正是定价可以维持的原因。

### 4.4 为什么敢承诺 60%（而不是 80%）

- 规则引擎的 40% 不可复用：不同客户的计价、质量系数、审批阈值必然不同。
- 客户定制 12 人日不可压缩：主数据脏、口径不一致是行业常态。
- 保守承诺 60%，实际交付 68.5%，留出 8.5 个百分点的缓冲给"客户差异"；若低于 60%，说明资产分层失败，需复盘而非改口径。

## 5. 第 3 个客户 ≤3 天上线

### 5.1 前提（不满足则不走 3 天）

| # | 前提 | 不满足的后果 |
| --- | --- | --- |
| 1 | 同业态（区域保洁/家政），业务规则不新增 | 需重新评估，2–4 周 |
| 2 | 字段/枚举/计价模型在配置范围内 | 需开发，按变更单计价 |
| 3 | 客户提供完整主数据（片区/阿姨/客户/订单） | 每天延迟 1 天 |
| 4 | 客户能在第 3 天参加 2 小时 UAT | 上线顺延 |
| 5 | 不接真实支付/短信（或已就绪） | 走桩，不影响上线 |

### 5.2 三天排程（24 小时）

| 天 | 时段 | 工作 | 产出 | 负责人 |
| --- | --- | --- | --- | --- |
| D1 | 09:00–12:00 | 配置片区、角色、计价、损耗科目、质量系数、审批阈值 | 配置文件包 | Agent + 人验收 |
| D1 | 13:00–17:00 | 导入主数据（片区/阿姨/客户），跑 Zod 校验，修 3 类以内错误 | 主数据通过率 100% | Agent |
| D2 | 09:00–13:00 | 导入近 3 个月订单/赔付 + 期初余额；跑对账 | 6 组对账 0 元差 | Agent + 人复核 |
| D2 | 14:00–17:00 | 抽样回放 20 单（建单→完成→赔付→提成→损益）；修配置 | 20 单全链路通过 | 人 |
| D3 | 09:00–12:00 | UAT 12 条 EARS + 8 条错误流 | UAT 报告 | 客户 + 人 |
| D3 | 13:00–15:00 | 培训（调度/财务/片区经理各 30 分钟）+ 录屏 | 培训录像、操作手册 | 人 |
| D3 | 15:00–17:00 | 上线、回归、交接；2 小时缓冲 | 上线确认书 | 双方 |

### 5.3 为什么能 3 天（而不是"拍脑袋"）

1. **代码零改动**：片区、计价、科目、阈值全部是配置；第 1 个客户的 5 模块代码原样复用。
2. **数据模板固定**：CSV/JSON 模板在第 1 个客户已固化，Zod 校验自动报错到字段。
3. **对账自动化**：`npm run verify` 同一套断言，换数据不换脚本。
4. **Agent 执行**：配置生成、数据清洗、回归、培训材料由 Agent 按 SOP 产出，人只做验收与客户沟通。

### 5.4 3 天失败时的兜底

- 第 1 天结束若主数据通过率 <90% → 顺延 1 天，不硬上。
- 第 2 天对账差异 >1% → 暂停上线，先查口径；不允许"带病上线"。
- 任何新增规则 → 立即转变更单，工期另计，不占用 3 天承诺。

**西乡塘净利变化**：`−2.66 + 1.017 = −1.643 万/月`（仍亏，但亏损收窄 **38.2%**）。

**敏感性**：

### 6.4 回本与 3 年 ROI

| 情景 | 年收益 | 年成本 | 回本周期 | 3 年净收益 | 3 年 ROI |
| --- | ---: | ---: | ---: | ---: | ---: |
| 满产（第 1 年即 100%） | 47.79 | 6.00 | **12.9 个月** | 80.36 | **127.6%** |
| **含爬坡（第 1 年 70%）** | Y1 33.45 / Y2–Y3 47.79 | 6.00/年 | **18.5 个月** | **66.02** | **104.8%** |
| 仅西乡塘，不复制 | 12.20 | 6.00 | 45 ÷ (12.20−6) = **3.7 年** | — | 不划算 |

**算式（含爬坡）**：
- 3 年收益 = 33.45 + 47.79 + 47.79 = **129.03 万**
- 3 年成本 = 45（一次性）+ 6 × 3（年运维/云/Token）= **63 万**
- 3 年净收益 = 129.03 − 63 = **66.03 万**；ROI = 66.03 ÷ 63 = **104.8%**
- 累计回本：Y1 末 −17.55 万；Y2 内转正；回本点 = 12 + 17.55 ÷ 41.79 × 12 ≈ **17.0 个月**（保守按 Y2 净现金流 41.79 计）

> 口径差异说明：按月末现金流精确累计为 18.5 个月；按年度中值估算为 17.0 个月。对外统一表述为 **"约 18 个月回本"**，取保守值。

### 6.5 未计入的收益（保守处理）

- 月报从 7 天到 T+1 的决策提速价值；
- 客户流失预警带来的复购提升；
- 定价/开片区决策的准确性提升；
- 品牌与合规（赔付留痕）价值。

以上**一律不计入 ROI**，作为安全边际。

## 7. 业务连续性：病倒两周，交付为什么不停

### 7.1 三项资产（L3 的核心）

| 资产 | 内容 | 存放位置 | 可交接性 |
| --- | --- | --- | --- |
| **代码库** | 源码、种子数据、测试、构建脚本、README、ADR（决策记录）、运行手册 | 远程 Git 仓库，每次里程碑推送 | 新执行人 `npm ci` 即可运行 |
| **Agent 库** | 8 个 Agent：需求澄清 / 数据建模 / 规则实现 / 测试生成 / UI 生成 / 对账校验 / 部署 / 周报草稿；每个含输入、输出、提示词、示例、验收标准 | `dev-team/` + 仓库内 `agents/` | 按 SOP 调用，不依赖个人记忆 |
| **SOP** | 8 段：启动→诊断→PRD→架构→实现→UAT→部署→陪跑；每段含检查清单、输入输出、DoD、回滚步骤 | `docs/` + `dev-team/references/` | 换人按清单执行 |

### 7.2 两周剧本（D0 交接，D1–D14 执行）

| 时间 | 动作 | 谁执行 | 产出 |
| --- | --- | --- | --- |
| D0 上午 | 冻结范围；移交只读资产；确认 3 个决策点授权 | 我 → 替补执行人 | 交接确认单 |
| D0 下午 | 替补执行人独立跑 `npm ci && npm run test:run && npm run verify` | 替补 | 全绿截图（<2 小时） |
| D1–D3 | 按当前 Sprint backlog 执行已排期任务；Agent 生成 PR | 替补 + Agent | 3 个 PR，测试门禁通过 |
| D4–D7 | 完成本周里程碑；每周一录播演示 | 替补 + Agent | 周报、演示视频 |
| D8–D11 | 下一 Sprint；回归集每日跑 | 替补 + Agent | 回归报告 |
| D12–D14 | 客户 UAT 准备；缺陷清零；上线/陪跑 | 替补 + 客户 | UAT 报告 |

### 7.3 为什么"不停"（可验证，不是口号）

1. **决策已前置**：范围、价格、上线标准三件事在合同里写死；两周内不需要我做新决策。
2. **知识不在脑子里**：每个模块有 spec（02/03 文档）、Agent playbook、测试夹具；替补不需要"问我在想什么"。
3. **门禁自动化**：`npm run test:run` + `npm run verify` + `npm run build` 是硬门禁，PR 不过不许合并；质量不依赖我的在场。
4. **48 小时可复现演练**：换一个会写代码的人（或一个全新 AI 会话），只读文档，48 小时内完成"构建→测试→部署→跑通 E2E"。这是 L3 的"不因人而异"判据。

### 7.4 不可代理的 3 件事（诚实边界）

| 事项 | 处理方式 |
| --- | --- |
| 客户关系与信任 | 提前录播周报 + 指定客户对接人；两周内不安排关键谈判 |
| 范围变更与报价 | 合同约定"两周冻结"；变更一律延后到我恢复 |
| 重大事故定责 | 预设升级触发：数据丢失、上线失败 >24h、客户投诉升级；触发后由替补执行"回滚 + 止损"，不做新决策 |

> 结论：**"交付不停"成立，"经营不停"不完全成立**。两周内可以保证在途项目按计划推进、质量门禁不破、客户有可见进展；但新签合同、涨价、危机公关必须等我回来。这是对客户和对自己都诚实的边界。

## 9. 假设清单

1. **税率 6%**：假定为现代服务业增值税；若客户要求 13% 专票，报价需另议。
2. **付款周期**：验收后 7 个工作日内到账；S1 按延后 30 天压力测试。
3. **月固定支出 3.2 万**：来自公司设定（生活费 1.5 + 房租 0.8 + 云 0.4 + 其他 0.5）。
4. **Token/云增量 0.6 万/项目**：按 8 周开发 + 30 天陪跑估算，实际按量结算。
5. **返工系数 40%**：一次完整返工 = 交付工作量的 40%（0.8 人月），用于人月产出最坏口径。
6. **第 2 客户净工作量 16.4 人日**：基于 52 人日总量与 68.5% 复用率推算，实际以第 2 客户复盘中位数校准。
7. **8 片区返工/空跑强度**：其余 7 片区返工按营收 1.5%、空跑按 1.0% 估算（西乡塘为 5.0%/2.6%），属假设，非客户数据。
8. **改善幅度**（赔付 −30% / 返工 −25% / 空跑 −40%）：行业经验值，不是承诺；以试点 8 周实测替换。
9. **阿姨替换成本 2,000 元/人、流失改善 12%**：假设值，用于人力收益估算。
10. **调度 0.5 FTE 释放**：按 5 名调度、问询工时减半的保守估计。
11. **年运维成本 6 万**：含云服务、Token、版本升级、季度对账；不含新增需求。
12. **青秀三项漏损为 0**：仅用于诊断对照口径，不代表真实为 0（见 02 文档假设 2）。

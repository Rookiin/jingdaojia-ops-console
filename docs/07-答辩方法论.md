# 07 · 答辩方法论（简版）

> 一页讲清：做了什么、怎么做的、老师会问什么。
> 详细版见 `docs/07-答辩方法论_详细版.md`；小程序端细节见 `docs/08-阿姨端小程序方案.md`。

---

## 一、一句话定位

客户要的不是 8 张表，是“西乡塘为什么连亏 14 个月、到底亏在哪”。我做了一条证据链：**4 个数据入口（每单 / 每笔赔付 / 每个阿姨 / 每个客户）+ 1 个出口（片区损益）**。

---

## 二、我交付了三样东西

1. **Web 经营看板**：5 个模块，回答“亏在哪”，可下钻、可对账、可模拟。
2. **阿姨端微信小程序**：只看自己的任务、300 米内定位打卡、拍服务前后照片、完成服务；不建单、不派单、不处理赔付。
3. **Agent 库 + SOP + 文档**：8 个 Agent 定义、诊断/方案/架构/测试/过程记录，换个人拿这套资产能接着交付。

---

## 三、从头到尾 8 步

1. **定位**：我是项目总监，不是程序员。人做判断和验收，Agent 做执行。
2. **重述**：把客户原话翻译成“四入口一出口”，先确认真问题。
3. **诊断**：量化六个痛点，对照青秀和西乡塘，把亏损拆成赔付 / 返工 / 空跑三项。
4. **定范围**：2 片区、5 模块、10 项明确不做，写清验收标准。
5. **定架构**：轻栈 + 业务规则纯函数 + 确定性数据；Web 和小程序共用同一套规则内核。
6. **组织执行**：1 人 + 8 Agent，分段时间盒，文件所有权，统一门禁收口。
7. **验证**：自动测试 + 损益对账闭合 + 小程序结构校验 + 人工演示。
8. **交付**：README、过程记录、Agent 库、远端仓库，边界如实声明。

---

## 四、答辩主线三句话

1. 我做的不是报表，是一条能解释亏损的证据链。
2. 我卖的不是工时，是换人能复现、换客户能复用的交付系统。
3. 我敢讲的不是“全做完了”，而是“每一分钱怎么算、哪一步没做、为什么不做”。

---

## 五、老师可能问的 10 个问题（简答）

**Q1：为什么只做 2 个片区、5 个模块？**
客户原话就是“先做 2 个片区，8 周给我看”。5 个模块是 4 个入口加 1 个出口，少一个账就算不准，多一个就做不完；其余 6 个片区是配置项，不是放弃。

**Q2：怎么证明“亏在哪”，而不是做了一堆报表？**
三件事：数字闭合（营收减各项成本等于净利）、两片区同口径对照（13 个点毛利差能被三项漏损解释）、可下钻可模拟（点开科目能看到明细，拖比例能看改善）。

**Q3：数据是不是你编的？**
数据是虚构的，这是考核要求；但口径和算式是真的。固定种子生成、没有随机、测试锁死关键结果、页面可一键重置；凡是推算的数字都标了“推算”。

**Q4：AI Native 是不是包装？Agent 到底干了什么？**
L3 的判据不是“AI 写了多少代码”，是“我走两周交付不停、换个人结果一致”。Agent 是执行单元，负责模块实现、测试补齐、文档初稿；人负责定范围、定契约、做门禁、验收。证据是 8 个 Agent 定义、S0–S5 时间盒、文件所有权和里程碑提交记录。

**Q5：为什么不用 TypeScript、后端、数据库、真实鉴权？**
约束先行：180 分钟现场可运行、不能接真实账号、规则必须可单测、要能复制。这个项目 95% 的复杂度在业务规则，不在请求并发；把后端拿掉，规则反而更可测。生产化路径（后端、登录、E2E、多租户）写在架构文档里，有触发条件。

**Q6：提成、损益、定责怎么保证算对？**
金额用整数分，时间统一上海时区，写操作带幂等键，状态机不可跳步；规则全是纯函数，不读时钟、不读随机；关键结果都有测试断言，损益有“分项合计等于净利”的对账校验。

**Q7：为什么自动定责永远不返回“无责”？**
防止系统默认“各打五十大板”。无责只能人工判定并填理由，这样“无法定责率”才会真实暴露。定责看证据分，证据不足进人工复核；金额超阈值升级审批；系统只给追偿建议，不自动扣款。

**Q8：45 万、人月产出、复用率、3 天上线，依据是什么？**
按结果和资产定价，不按工时。数字都有算式和压力测试：最坏的现金情景也不为负；复用率按人日保守计算；3 天只承诺同业态，主数据不完整就顺延，不硬上。

**Q9：多做了一个小程序，两端规则怎么保证一致？**
阿姨端只做“看任务、定位打卡、拍照、完成”，不建单、不派单、不碰赔付。状态机、金额、账期、距离、打卡/完成规则与 Web 共用一套内核：先同步到小程序目录，再用校验脚本做哈希和纯净性检查，防止两端漂移。

**Q10：哪些没做？你病倒两周真的不停吗？**
主动交底：没有真实鉴权、没有后端和数据库、没有浏览器 E2E、没有覆盖率工具；工单规模为演示下调；小程序和 Web 数据各自本地存储、不实时同步。连续性上，“交付不停”成立，因为范围、契约、门禁和 Agent 库都在；“经营不停”不完全成立，客户关系、变更报价、重大事故定责仍然只能等我。

## 六、现场注意 5 条

1. **先结论后功能**：先讲“亏在哪”，再讲怎么做到。
2. **不把虚构说成真实，不把假设说成事实**：数据、对照口径、改善幅度都要说明边界。
3. **不把 Agent 说成全自动**：人做判断，Agent 做执行，门禁做质量。
4. **主动交底未做项**：尤其是两端不互通、无鉴权、无 E2E。
5. **不现场改代码**：演示前重置数据、跑一遍 `npm run verify`（含小程序校验），准备好离线包。

---

## 七、30 秒陈述

> 净到家要的不是 8 张表，是“西乡塘为什么连亏 14 个月、亏在哪”。我用 5 个模块把每单、每笔赔付、每个阿姨、每个客户的数据汇入片区损益，把亏损拆成可执行的漏损项。阿姨端小程序负责一线打卡和拍照，和 Web 共用同一套规则内核。交付上按 L3 组织：人做判断，Agent 做执行，代码库 + Agent 库 + SOP 做记忆，测试和对账做门禁。现在能复跑、能演示、能交接；生产级的鉴权、并发和真实数据接入，是我二期要补的边界。

# 08 · 阿姨端微信小程序方案

> 目标：给一线保洁阿姨一个只用"看任务、打卡、拍照、完成"的手机端，复用 Web 看板的业务内核与数据契约，不重写规则，也不创建新工单。

## 1. 范围

**做**
- 查看自己的任务（待打卡 / 服务中 / 已完成）。
- 到店定位打卡：距客户 **300 米内**、至少 1 张服务前照片。
- 完成服务：至少 1 张服务后照片；客户签字允许 Web 看板后补（`signature_pending=true`）。
- 操作记录写入工单：`checkin_at`、`checkin_location`、`photos_before/after`、`field_events`。
- 适老交互：大字号、大按钮、每屏一个主操作、错误提示说人话。

**不做**
- 不创建工单、不派单、不改金额、不处理投诉/赔付、不展示提成。
- 不做登录鉴权（演示身份选择）、不做后端/云开发、不做两端实时同步。
- 不做真实上传：照片只保存在手机本地。

## 2. 复用方式（单一事实源）

| 能力 | Web 源文件 | 小程序 |
| --- | --- | --- |
| 状态机/枚举 | `src/domain/types.js` | `miniprogram/core/types.js`（同步副本） |
| 金额工具 | `src/domain/money.js` | `miniprogram/core/money.js` |
| 账期归属 | `src/domain/period.js` | `miniprogram/core/period.js` |
| 距离计算 | `src/shared/geo.js` | `miniprogram/core/geo.js` |
| 打卡/完成规则 | `src/shared/field-actions.js` | `miniprogram/core/field-actions.js` |
| ID/幂等键 | `src/lib/id.js` | `miniprogram/core/id.js` |
| 演示任务 | `src/data/field-tasks.js` | `miniprogram/data/seed.js` / `seed.json` |
| 写入口（Web） | `src/store/actions.js` 的 `fieldCheckIn/fieldComplete` | 同一内核，小程序经 `store.js` 调用 |

- 小程序根目录不能 import 仓库根之外的代码，因此用 `scripts/sync-miniprogram.mjs` 复制内核到 `miniprogram/core/`，并生成 `MANIFEST.json`（逐文件 sha256）。
- `scripts/check-miniprogram.mjs` 校验：生成文件未被手改、源文件未漂移、core 内无 `wx.*`/Node API/CommonJS、阿姨端无 `createOrder`、页面四件套齐全、app.json 权限声明完整。
- `periodOf` 已改为按固定 +08:00 算术计算（Web 原有 A10 行为不变），避开微信 iOS 基础库 Intl 支持不全的问题。

## 3. 页面与适老设计

| 页面 | 作用 | 主操作 |
| --- | --- | --- |
| `pages/login` | 选择阿姨（姓名 + 手机尾号 + 片区 + 待办数） | 进入我的任务 |
| `pages/tasks`（tab） | 我的任务卡片：日期时间、客户、地址、状态大标签 | 去打卡 / 继续完成 |
| `pages/detail` | 三步进度 + 客户地址与导航 + 打卡区 + 完成区 | 获取位置、拍照、确认打卡、完成服务 |
| `pages/mine`（tab） | 本人信息、今日完成数、本地占用、边界说明 | 切换名字、重置演示数据 |

- 正文 34rpx（≈17px），标题 46rpx，关键数字 64rpx；主按钮高 104rpx、通栏、深绿底白字。
- 不使用图标按钮和滑动手势；所有按钮都是动词短语（"获取我的位置""拍服务前""确认打卡"）。
- 错误文案口语化，例如："距离客户 820 米，超出 300 米范围，请到客户家门口再试。"定位被拒时给"去设置"入口。
- 打卡与完成各有二次确认；重复点击由幂等事件挡住，不会重复记账。

## 4. 业务规则

**打卡（`checkInOrder`）**
- 入口条件：工单状态 `assigned`。
- 必填：打卡时间（设备当前时间，带 +08:00）、定位经纬度、至少 1 张服务前照片。
- 客户坐标来自种子（虚构）；距离用 haversine 计算，>300 米返回 `OUT_OF_RANGE` 并显示实际距离。
- 成功写入：`status='checked_in'`、`checkin_at`、`checkin_location={lat,lng,accuracy,distance_m,at}`、合并照片、追加 `field_events`（id = `工单:checkin`）。
- 已有打卡事件时重复调用返回 `idempotent`，不覆盖首次定位。

**完成（`completeOrder`）**
- 入口条件：工单状态 `checked_in`。
- 必填：完成时间、至少 1 张服务后照片。
- 成功写入：`status='completed'`、`completed_at`、合并照片、`signature_pending=!signature`、追加事件（id = `工单:complete`）。
- 重复调用幂等。

**照片**
- `wx.chooseMedia` 相机/相册，压缩图，每步最多 3 张。
- 临时路径立即 `wx.getFileSystemManager().saveFileSync` 持久化，避免重启失效。
- 演示环境不做上传；"我的"里可查看本地占用并重置演示数据。

## 5. 数据与边界

- 小程序只带 **3 位阿姨、6 张 2026-11-02 在途任务、6 位客户快照**（约 8.7KB），不含 1,806 单全量种子，避免微信单 key 1MB 限制。
- 本地存储 key `njdao:mp:v1`，带版本号；首次启动注入种子，之后整份状态本地持久化。
- 客户坐标是按片区中心合成的**虚构坐标**（约 ±440 米偏移），不是真实地理编码；地址均为"示例路（虚构）"。
- 与 Web 看板**数据不互通**：两端同一套规则/种子/契约，各自本地存储；跨端同步需接后端，本期明确不做。
- 真机使用定位需正式 AppID 并声明隐私接口；开发者工具用测试号 + 模拟位置即可完整演示。

## 6. 演示脚本（微信开发者工具）

1. 打开微信开发者工具 → 导入项目 → 目录选 `miniprogram/` → AppID 选"测试号"。
2. 详情 → 本地设置：勾选"不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书"。
3. 编译后进入"选择我的名字"，任选一位阿姨（例如黄雪梅 C-0001）。
4. 打开一张"待打卡"任务，在"模拟位置"里填入该客户坐标（下表），点"获取我的位置"→ 应显示"距离客户约 0 米"。
5. 点"拍服务前"（开发者工具可选本地图片模拟相机）→ 点"确认打卡"→ 二次确认后状态变"服务中"。
6. 切到"服务中"的任务 → 拍服务后照片 → "完成服务"→ 状态变"已完成"，提示"客户签字由办公室补录"。
7. 把模拟位置改到远处（如纬度 +0.02）再对"待打卡"任务打卡 → 应被拒绝并显示实际距离。
8. 关闭小程序重新进入 → 状态和照片仍在；"我的"→ 重置演示数据 → 回基线。

## 7. 验证

```bash
npm run sync:mp     # 生成 core/seed/MANIFEST
npm run check:mp    # 结构 + 哈希 + core 纯净性 + 无建单
npm run test:run    # 14 文件 / 136 例（含小程序 store 11 例）
npm run verify      # test + build + check:mp
```

- 纯函数：距离、打卡门禁、超范围、缺照片、幂等、签字后补。
- 小程序 store：种子注入、按阿姨过滤、打卡落库、重启读取、重置、读取失败降级、NOT_FOUND。
- 结构：`check:mp` 验证 6 个 core 文件、31 个工程文件、权限声明、无 `createOrder`。
- 未自动化：页面点击、相机、真机定位（无微信模拟器）；按第 6 节人工走查。

## 8. 已知限制与下一步

1. 无真实登录与 RBAC；上线前接入企业微信/手机号授权与服务端鉴权。
2. 照片仅本地保存，未做对象存储上传、压缩策略与隐私合规（人脸/门牌）。
3. 定位只做 300 米硬校验，未处理漂移、室内误差与弱网重试；生产建议加"拍照门牌 + 异常上报"。
4. 两端数据不互通；要实时联动需加后端 API（可复用同一套 `field-actions` 与状态机）。
5. 真机发布需注册 AppID、配置 `requiredPrivateInfos` 与隐私协议弹窗。

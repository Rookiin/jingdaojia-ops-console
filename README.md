# 净到家保洁 · 片区经营看板（AI Native 交付试点）

一人软件公司（1 人 + Agent 团队）为净到家保洁交付的第一个试点：一套"看住每一单、每一笔赔付、每个阿姨、每个客户"的台账与经营看板，并用同一个页面直接回答客户最关心的问题——**西乡塘那个亏的片区，到底亏在哪。**

一句话结论：西乡塘月亏 **2.66 万**，其中 **3.38 万/月**是可管的三项漏损——赔付 1.40 万、免费返工 1.30 万、空跑改约 0.68 万，占营收 **13.0%**；三项各降 30% / 25% / 40% 后，该片区净利回到 **−1.643 万**。青秀同期净利 **+2.44 万**，两片区合计 **−0.22 万**。

---

## 1. 快速开始

```bash
npm install
npm run dev        # http://localhost:5173
```

| 命令 | 作用 |
| --- | --- |
| `npm run dev` | 本地开发服务器（5173） |
| `npm run test:run` | 运行 10 个测试文件 / 96 个用例 |
| `npm run verify` | 串联门禁：`test:run && build` |
| `npm run build` | 生产构建到 `dist/` |
| `npm run preview` | 本地预览构建产物 |

环境：Node + npm；运行时依赖只有 `react@18.3.1` / `react-dom@18.3.1`。

## 2. 五分钟演示脚本

1. 打开首页，页头显示账期 `2026-10`、`8 片区 · 98 阿姨 · 1800 工单`；五个页签对应 5 个模块。
2. **M1 工单追溯**：按片区/状态/关键词筛选；点开任意工单看状态时间线、证据链、关联投诉与赔付；"新建派单"可创建新单并依次执行派单 → 签到 → 完成（缺签字会被拒绝）。
3. **M2 赔付管理**：对已完成工单新建赔付（原因 + 金额），先"评估"看证据分与责任方，再提交；详情面板可审批；>500 元必须财务角色；重复提交与重复审批均为幂等。
4. **M3 阿姨工时提成**：月结总表 98 人，点开阿姨看到质量系数来源（calculated / override）与逐单提成；可设人工覆盖系数并即时重算；支持 CSV 导出。
5. **M4 客户档案**：客户 360（历史单 / 投诉 / 赔付 / 流失信号），手机号脱敏；发生过赔付的客户自动带"赔付关注"标签。
6. **M5 片区损益**：8 片区净利排行；西乡塘的漏损拆解（赔付 / 返工 / 空跑）与占比；14 期趋势；"假设测算"拖动三项削减比例，实时看新净利与改善额（页面标注"假设"，不写回原始账）。
7. 演示结束点"重置演示数据"回到基线，结果可复现。

- 测试覆盖：领域纯函数、selectors 种子对账、actions 状态机与幂等/审批角色、5 个页面 SSR 冒烟。
- 生产就绪记分卡：见 `docs/05-测试与就绪记分卡.md`，当前总档 **Bronze**（短板：无鉴权、无指标）。

## 6. 边界声明（重要）

1. **数据全部虚构**：由 `src/data/generate.js` 以固定种子 `20261031` 生成；无任何真实客户、阿姨、手机号、地址或凭据。
2. **无真实后端**：纯前端 + localStorage（key `njdao:v1`），单机单浏览器；非多租户、无并发同步。
3. **无鉴权**：审批层级由 `approveCompensation` 的入参 `role` 模拟，不是真实登录/RBAC。
4. **无外部服务**：短信、支付、地图、对象存储均为空实现或占位；照片与签字是 `mock://` 字符串。
5. **不在本期范围**：账期锁定与红冲、批量派单、消息通知、移动端适配、真实导出审计。
